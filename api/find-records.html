Find Records

Filter records by any property with compound filter groups, or batch-fetch a specific set of records by their IDs in a single request.

Filter

POST /api/v1/objects/{object}/records/filter

Compound filter over any object type. filter_groups are combined with OR; the filters within one group are combined by the group's logical_operator (AND / OR). Two examples are shown below - a single-field filter (contacts in one city) and a multi-field filter (contacts by owner + city + recent activity).

Path parameters

object string · requiredObject type - one of contact, company, deal, note, meeting, task.

Request body

filter_groups array · requiredOne or more groups. Groups are combined with OR. Each group has logical_operator (AND/OR, defaults to AND) and a filters array.
filters[].field_path string · requiredThe property name to filter on. Always snake_case (e.g. owner_id, city, last_activity_date).
filters[].operator string · requiredComparison operator - see the table below.
filters[].value / values anyvalue for single-value operators; values (array) for IN, NOT_IN, BETWEEN. Omit for IS_NULL/IS_NOT_NULL.
pagination object{ page, page_size }. Same defaults as list endpoints (page 1, size 20, max 100).
sort object{ field, direction }. direction is ASC or DESC. Field must be snake_case.

Operators

OperatorValue fieldWorks with
EQUALSvalueAll field types
NOT_EQUALSvalueAll field types
GREATER_THANvalueNumbers, dates
LESS_THANvalueNumbers, dates
GREATER_THAN_OR_EQUAL_TOvalueNumbers, dates
LESS_THAN_OR_EQUAL_TOvalueNumbers, dates
BETWEENvalues (array of 2)Inclusive range - numbers, dates
INvalues (array)Match any value in the array
NOT_INvalues (array)Exclude any value in the array
IS_NULL-Field is empty
IS_NOT_NULL-Field is not empty
CONTAINSvalueSubstring match - text fields
STARTS_WITHvaluePrefix match - text fields
ENDS_WITHvalueSuffix match - text fields

Body keys accept both cases

You can send filter_groups/field_path (snake_case) or filterGroups/fieldPath (camelCase). Both are accepted. Field names inside field_path and sort.field are always snake_case - e.g. created_at, not createdAt.

Returns

The matching records, paginated the same way as List Records (results, metadata with page, page_size, total_elements, total_pages, has_next, has_previous).

Batch Fetch by IDs

When you already have a list of record IDs, hit the same Filter endpoint with an IN filter on id to get them all in a single call. This isn't a separate endpoint — it's the filter pattern you'll reach for most often.

When to use it

  • Hydrating associated records. A Get Record or List Records response embeds associations as {id, association_name} pairs. One call replaces N individual Get Record calls.
  • Working from a set of IDs - from a search result, a webhook payload, a spreadsheet import, or anywhere else you already have IDs on hand.

Request body

A single filter group with one IN filter on id. Pass the list of ids in values. See the Filter section above for the full body schema.

POST /api/v1/objects/{object}/records/filter 
curl 'https://api.dreamteamcrm.ai/api/v1/objects/company/records/filter' \
  -X POST \
  -H 'Authorization: Bearer <YOUR_TOKEN>' \
  -H 'Content-Type: application/json' \
  -d '{
  "filter_groups": [
    {
      "filters": [
        {
          "field_path": "id",
          "operator": "IN",
          "values": [1011597, 1011598]
        }
      ]
    }
  ]
}'
