Recipes

Meetings, transcripts & summaries

One recipe answers a whole family of questions - “what meetings has this contact had?”, “what was the sentiment?”, “where’s the summary?”, “give me the transcript.” They’re all reads: start from a contact, follow the association to the meeting, read the meeting’s AI summary, highlights and sentiment - then hop one more link to the recording for the transcript itself and the media. The same pattern works from a company or deal - pass ?associations=meeting on any of them.

Before you start

Two things carry through every step. These are all reads - meetings and recordings are ingested by the call integrations (Recall.ai, Fathom, Clari…), so there’s no create endpoint, and their AI fields fill in asynchronously (wait for the recording’s status_code: "TRANSCRIPT_DONE"). And like ai_about, the AI fields - and the raw transcript - come back as JSON-encoded strings to parse; ai_formatted_transcript is already an object.

Step 1 · List the meetings on a contact

Retrieve the contact and embed its meetings by passing ?associations=meeting. Embedded associations come back as {id, association_name} pairs - ids only.

Take a meeting id from associations.meeting.records into Step 2. Got several? Fetch them all in one call with Hydrate by IDs (object=meeting). More than 100 meetings on one record are paged with the dedicated associations endpoint.

GET /api/v1/objects/contact/records/{id}

Step 2 · Read the meeting - summary, highlights, sentiment

Retrieve the meeting by an id from Step 1. It carries the meeting intelligence: ai_sentiment (Good / Neutral / Bad) as a plain value, and ai_meeting_summary, ai_meeting_highlights, ai_meeting_post_brief as JSON-encoded strings - parse each after reading. participants is a comma-separated list of attendee emails.

The meeting does not hold the transcript - that lives on the recording. Continue to Step 3 for the transcript and media.

Step 3 · Follow the recording for the transcript

The transcript and media live on the recording, one link on from the meeting. It’s two calls - use the tabs to switch between them: first read the meeting’s recording association for the id, then retrieve the recording.

The recording gives you two transcript shapes: transcript (the raw provider transcript, a JSON-encoded string of segments) and ai_formatted_transcript (a cleaned object of speaker turns with timestamps). audio_url and video_url are time-limited signed URLs - fetch them promptly and don’t store the URL itself.

Wait for status_code: "TRANSCRIPT_DONE" before relying on the transcript fields.

2 calls
GET /api/v1/objects/meeting/records/{id} 
# meeting → recording id
curl 'https://api.dreamteamcrm.ai/api/v1/objects/meeting/records/1090142?associations=recording' \
  -H 'Authorization: Bearer <YOUR_TOKEN>'
{
  "id": 1090142,
  "type": "meeting",
  "associations": {
    "recording": {
      "records": [
        {
          "id": 1090777,
          "association_name": "meeting_recording_assoc"
        }
      ],
      "metadata": {
        "total": 1,
        "has_more": false
      }
    }
  }
}
