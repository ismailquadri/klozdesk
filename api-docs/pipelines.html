Pipelines

List pipelines and retrieve a pipeline with its full stage layout. Pipelines organize deals through your sales stages, from lead to close. A workspace has exactly one pipeline today, so List Pipelines returns a single entry - the endpoint is plural because the resource is, not because a workspace can hold several.

List Pipelines

GET /api/v1/pipelines

Query parameters

page integerPage number, starts at 1. Defaults to 1.
page_size integerPage size. Default 20. Max 100 - higher values are silently capped at 100 (no error). Defaults to 20.
sort stringSort spec

Returns

Paginated pipeline list.

Get Pipeline by ID

GET /api/v1/pipelines/{id}

Path parameters

id integer · required

Returns

The pipeline with all its stages nested under stages. Each stage carries the fields below - use them to decide the "next" stage or to detect a closed deal.

Stage fields

stage_orderInteger. Position of the stage in the pipeline (1-based).
stage_categoryCommon values: Early Stage, Mid-Level Stage, Late Stage, Closed Won, Closed Lost. An admin configures the stages for the workspace, so read the labels from the response rather than assuming this set.
win_probabilityInteger 0-100. Used for pipeline forecasting.
is_closedBoolean. true for terminal stages (Closed Won / Closed Lost). Once a deal moves to an is_closed: true stage it's considered done.
entry_criteriaOptional free text describing what should be true before a deal enters this stage.

Assigning stages to deals

Use stage_id from this response when creating or updating a deal via the Records endpoints. pipeline_id on the deal must match the pipeline that owns the stage.
